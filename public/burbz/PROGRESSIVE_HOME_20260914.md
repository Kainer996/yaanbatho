# Progressive Home — integration candidate

This changes Home presentation only. It is based on `48ea7df10cfc6ea94cef5cb00837b214f28ff0d2`; release and deployment remain with the existing Burbz visual polish owner. No build version, global navigation, tutorial, economy, room ownership, reward or game-save schema is changed here.

When no optional features are open, Home shows two large usable panels: bird discovery and the current quest with the shared Equipment control. Kitchen, Training and Hospital require both their existing feature gate and the canonical built room. Stores requires its existing gate. Villages requires an actual saved holding. Empty but usable rooms remain visible. Completed building notices share Buildings rather than adding another permanent feature section; its readable modal retains each existing completion action and the villages route.

A weighted responsive grid gives the newest usable feature the largest area. Canonical construction/first-village dates provide the initial order; undated old saves have a deterministic fallback. A separate `burbz_home_panel_preference_v1` local-storage display preference remembers newly observed usable sections across reload. It never creates an unlock and discards a remembered feature when the current save does not allow it. Identical renders do not rewrite the preference.

Artwork gets more space early and contracts as rooms become usable. In short landscape and the densest small portrait, the same Equipment DOM button moves beside the artwork and returns as space allows, preserving its existing handler and inventory sheet. Merlin uses the existing artwork and care owner, with Home-only scaling and placement; no 3D work or new art is included.

Panels show bounded previews (two items, or one village) and real counts; the full native room/Stores actions remain on their 44px headings. Buildings opens all actual completed notices. There are no miniature navigation tabs or pagination arrows. Details are shown only when the measured panel can contain them. The scanner session still uses its original DOM, explicit media gestures and close behavior. A ResizeObserver and one coalesced animation-frame layout update respond to viewport/state changes; no periodic/per-frame layout loop is added.

## Integration contract

- `scanHomeDeskSnapshot()` adds `rooms` for Kitchen/Training/Hospital, each with canonical `built` and `builtAt`, plus the earliest real `featureDates.village`.
- The separate opening/gate work remains authoritative through `featureGateOpen`; Home does not duplicate lesson/quest ordering.
- Existing Home `scan_home.css`, `scan_home_core.js` and `scan_home.js` consuming URLs, all three worker lists and the guarded updater must receive one matching release-owned pin when integrated. This candidate intentionally does not bump release/cache markers.
- Other Home core route/action projections keep their earlier contracts. The new playable gates apply to panel visibility and care previews.
- `tests/test_opening_home_projection_v405.cjs` already expects ready-to-open notices to be excluded, but this baseline includes them (the first expected count is 1, actual 2). This work preserves their actual opening actions rather than changing that pre-existing mismatch.
